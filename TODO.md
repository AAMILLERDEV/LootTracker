# TODO

Planned features for LootTrackerTBC. Not in any particular order.

- [x] **Session Management (redesign)** — implemented 2026-08-12. Real pain point: "reset" used to be the only session boundary, so runs could only be compared by wiping everything between them. Now:
  - `LootTrackerDB.sessions[]` replaces the old flat `sources`/`log` at the DB root; each session holds its own `sources`/`log`/`startTime`/`endTime`/optional `name`. Existing installs migrate their old flat data into session 1 automatically (`InitDB` in Core.lua) — nothing is lost on upgrade.
  - **Manual split**: the session picker button (its own row, below Collapse All / view toggle) → "Start New Session..." prompts for an optional name (blank auto-labels as "Session N"), closes out the active session (stamps `endTime`), and starts a fresh one *without deleting* the old one. `LT.StartNewSession` in Core.lua.
  - **Session picker**: same button opens a dropdown listing every session newest-first, with a checkmark on whichever is currently viewed; live tracking always continues in the active session regardless of which one is being *viewed* (`viewedSessionIndex` in UI.lua — `nil` means "follow whatever's active", a number pins to that specific past session). Persisted across logins.
  - **Reset repurposed**: resetting the *active* session wipes it in place (tracking continues); resetting a *past* (closed) session deletes it outright, since there's nothing live left to preserve — the Options menu label and confirmation text switch between "Reset current session" / "Delete this session" accordingly. `LT.ResetSession` in Core.lua.
  - Auto-splitting (e.g. on logout, or after N hours idle) is still a reasonable follow-up, but wasn't needed to solve the reported problem.

- [x] **Gold/hr Breakdown** — implemented 2026-08-12. A "Gold/hr" line (plus "(Xh Ym elapsed)") now appears in the session-total tooltip, computed from the currently *viewed* session's `startTime`/`endTime` — so it works for past sessions too, not just the live one.
  - **Idle-time decision**: went with plain wall-clock elapsed time (`endTime or now() - startTime`), not an active-play-time heuristic — WoW gives addons no reliable "the player is actually farming right now" signal, so anything fancier would just be guessing. The tool for keeping the rate honest is the **manual session split** built above: start a new session before you go AFK, and idle time never gets averaged into the rate at all. Documented so this isn't mistaken for an oversight.
  - Suppressed for the first `MIN_ELAPSED_FOR_RATE` (60s) of a session so one early drop can't produce an absurd extrapolated rate. See `totalHitbox`'s tooltip and `FormatDuration` in UI.lua.

- [x] **Item Filter (show/hide items)** — implemented 2026-08-12. Right-click any item row to hide it (fully excluded from lists *and* totals). Options > Manage Hidden Items no longer opens a separate dropdown — it now swaps the content area itself into a dedicated hidden-items list (a minus icon beside each entry; click one to unhide it), the same way Grouped/Item/Timeline swap the content area for each other. "Back to Loot" (the view-toggle button, relabeled while active) returns to whatever view you were on. See `RenderHiddenItems`/`ToggleHiddenItemsView` in UI.lua and `LT.IsItemHidden`/`LT.SetItemHidden`/`LT.GetHiddenItems` in Core.lua.

- [x] **Item Summary View** — implemented 2026-08-12. Third view mode (cycle via the view button: Grouped → Item → Timeline → Grouped) that aggregates by *item* across all sources instead of by source, e.g. "every Chunk of Boar Meat looted this session, total count, total value" as one row. See `BuildItemSummary`/`RenderItems` in UI.lua.

- [x] **Disenchant Tracking** — implemented 2026-08-12, **corrected 2026-08-13** after a live repro showed the first version never tracked anything. Root cause: a disenchant loot window's `GetLootSourceInfo` GUID (`Item-<n>-0-<id>`) has a different field layout than Creature/GameObject GUIDs (only 4 dash-separated fields, not 7) — the original code's parser read a nonexistent field and silently got `nil`. Worse, even parsed correctly, `<n>` turned out to be an internal quality/ilvl loot-bracket id, *not* the disenchanted item's itemID (disenchant loot tables are shared across many items of the same bracket) — so there was never anything usable to extract from that GUID at all.
  - Fixed approach: the target item is captured off `ITEM_LOCKED` at the moment you click it while a spell is targeting (works for any item-targeted spell, not just Disenchant — harmless, since it's only trusted once the very next spell to resolve is confirmed as Disenchant), then carried forward and attributed directly to the loot window that opens within `DISENCHANT_WINDOW` (3s) afterward — bypassing the loot window's own (useless) source GUID entirely. Gated additionally on that raw GUID still looking like `Item-...` or being absent, so a genuine Creature/GameObject loot window opening while the timer happens to still be running is never misattributed.
  - `ParseGUID` in Core.lua no longer has an `Item` branch at all (dead code, since real Item GUIDs can't be parsed usefully); it instead recognizes a synthetic `"Disenchant-<itemID>"` sentinel that `CollectSlotSources` constructs once the item is known, so the rest of the crediting pipeline treats it like any other source with no special-casing.
  - New source kind `"disenchant"`, keyed by the disenchanted item's (now correct) itemID; label resolves the item's name live via `GetItemInfo` as "Disenchanted: `<item>`". See `pendingDisenchantItemID`/`lastDisenchantItemID`/`ITEM_LOCKED` handling in Core.lua and `SourceLabel` in UI.lua.
  - **"Loot pool" clarified and implemented**: not a fourth view, but a **"Show disenchants only" filter** (Options menu checkbox) that composes with the Grouped/Item/Timeline views, so disenchant results can be seen grouped by source, by item, or as a timeline.
  - Added a permanent `/lt debug` toggle (was previously a hardcoded `DEBUG` constant needing a code edit) — this is what made diagnosing the original bug possible from a single live repro instead of guessing blind.

- [x] **Auctionator-disabled UX** — implemented 2026-08-12. `LT.AuctionatorStatus()` in Core.lua distinguishes "loaded" / "disabled" (found via `GetAddOnMetadata` but not `IsAddOnLoaded`) / "missing". When disabled, a hint now appears in the Options menu and in the session-total tooltip: "Auctionator is installed but disabled — enable it to see AH values." Reading its price data while disabled remains impossible (its `SavedVariables` table only exists once its own `ADDON_LOADED` runs), so this is UX-only, as expected.
